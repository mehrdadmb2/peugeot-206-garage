# معماری سامانه و جریان داده

## اجزای اصلی

| جزء | مسیر | مسئولیت |
|---|---|---|
| داشبورد | `index.html`, `assets/js/app.js` | نمایش داده، فیلتر، نمودار و تعامل کاربر |
| موتور سوخت مشترک | `assets/js/fuel-intelligence.mjs` | اعتبارسنجی سوخت‌گیری، موازنهٔ باک، بازهٔ مصرف و هزینهٔ سفر |
| موتور جریمه مشترک | `assets/js/fine-intelligence.mjs` | تشخیص قبض دوبرگی، موعد یادآور و هشدار مبلغ احتمالی |
| موتور هزینه | `assets/js/vehicle-cost-intelligence.mjs` | تجمیع هزینهٔ مالکیت و تحلیل سفر |
| پروفایل خودرو | `assets/js/vehicle-profile.js` | رندر فنی پیشرانه، تیپ، ظرفیت‌ها و سطح قطعیت داده |
| تقویم مشترک | `assets/js/persian-calendar.js` | تبدیل تاریخ با timezone ثابت تهران، مرز روز/ماه/سال و نمایش تاریخ شمسی |
| موتور کیلومتر | `assets/js/odometer-intelligence.js` | اعتبارسنجی توالی کارکرد، رد عقب‌گرد/جهش ناممکن و اعمال reset صریح |
| Worker | `worker/src/index.js` | وب‌هوک تلگرام، فرمان‌ها، پارسر، API و ذخیره‌سازی GitHub |
| Snapshot builder | `scripts/build-dashboard.mjs` | محاسبهٔ دادهٔ ازپیش‌آماده برای GitHub Pages |
| GitHub Actions | `.github/workflows/` | تست، ساخت Snapshot و کارهای زمان‌بندی‌شده |

## مسیر ثبت یک رویداد

1. کاربر پیام را در چت خصوصی تلگرام می‌فرستد.
2. Telegram Webhook پیام را به Worker می‌رساند.
3. Worker شناسهٔ فرستنده و نوع ورودی را اعتبارسنجی می‌کند.
4. پیام به رویداد ساختاریافته تبدیل و از نظر تکراری‌بودن بررسی می‌شود.
5. Worker فایل ماه مربوط در `data/logs/YYYY-MM.json` را به‌روزرسانی می‌کند و `data/index.json` را همگام می‌سازد.
6. GitHub Contents API تغییر را در شاخهٔ `main` ذخیره می‌کند.
7. داشبورد Snapshot معتبر را می‌خواند یا در صورت قدیمی/نامعتبر بودن از فایل‌های خام استفاده می‌کند.

## منبع حقیقت و فایل‌های داده

- `data/logs/YYYY-MM.json`: دفتر اصلی رویدادهای ماهانه؛ منبع حقیقت برای سوخت، جریمه، تعمیر و هزینه.
- `data/index.json`: فهرست ماه‌ها، تعدادها و زمان آخرین تغییر.
- `data/config.json`: تنظیمات خودرو، افراد، سرویس‌ها و پارامترهای مدل.
- `data/dashboard.json`: خروجی محاسباتی مشتق‌شده؛ قابل بازسازی از لاگ‌ها و تنظیمات است.
- `data/deleted-events.json`: بایگانی رویدادهای حذف‌شده.
- `data/pending-duplicates.json`: مواردی که نیازمند تأیید تشخیص تکراری‌اند.
- `data/reminder-state.json`: وضعیت چرخهٔ هشدارها.

Snapshot جایگزین سوابق ماهانه نیست. اگر Snapshot خراب یا قدیمی شود، باید از داده‌های خام بازسازی شود.

## موتورهای محاسباتی مشترک

### سوخت

هم داشبورد و هم Worker از `assets/js/fuel-intelligence.mjs` استفاده می‌کنند. ورودی آن رویدادهای سوخت و تنظیمات `fuelModel` است. خروجی شامل نمونه‌های معتبر، نمونه‌های ردشده، بازهٔ مصرف، قیمت تخمینی هر لیتر، سطح اطمینان و تخمین سفر است.

### جریمه

هم داشبورد و هم Worker از `assets/js/fine-intelligence.mjs` استفاده می‌کنند. فقط متن/فیلد صریح «دوبرگی» مجاز به ساخت مهلت خودکار است. تشخیص دوربین یا نوع نامشخص، به‌تنهایی موعد یا مبلغ دوبرابر نمی‌سازد.

## پروفایل فنی و کاتالوگ قطعه

`data/config.json` شامل پروفایل مهندسی خودرو و `partCatalog` است. نسخهٔ 3.27.0 کاتالوگ را به ۱۲۶ قطعه در ۱۵ گروه و ۳۵ سرویس/آزمون گسترش می‌دهد. هر قطعه می‌تواند سطح اهمیت (`criticality`)، وضعیت سازگاری (`fitmentStatus`)، روش بازرسی، نشانه‌ها و فیلدهای شناسنامه داشته باشد.

رویداد نصب قطعه می‌تواند برند، مدل، شماره فنی، سریال، مشخصات، تعداد، ضمانت، فروشنده، فاکتور و محل نصب را ذخیره کند. تاریخ ضمانت شمسی به ISO نرمال می‌شود، اما برچسب شمسی هم برای نمایش حفظ می‌شود. قطعات حساس و تیپ‌محور باید با VIN، کد گیربکس، ABS و قطعهٔ موجود تطبیق داده شوند؛ برنامه شماره OEM یا فاصله تعویض را حدس نمی‌زند.

مشخصات موتور TU3/K6D و Euro III در این پرونده مرجع تیپ و محتمل است؛ تا ثبت کد موتور و اسناد اختصاصی، سطح داده `reference_only` می‌ماند.

## امنیت

- توکن GitHub و توکن تلگرام فقط در Worker Secrets هستند.
- APIهای محافظت‌شده از `API_ACCESS_TOKEN` استفاده می‌کنند.
- دسترسی به مدارک خصوصی از `DOCUMENTS_ACCESS_TOKEN` و KV خصوصی استفاده می‌کند.
- محدودیت فرستندهٔ تلگرام با `ALLOWED_TELEGRAM_USER_ID` اعمال می‌شود.
- مقادیر Secret و شناسهٔ KV نباید به README، HTML یا فایل‌های عمومی وارد شوند.

## بازیابی و عدم وابستگی‌ها

- داشبورد می‌تواند دادهٔ خام GitHub را بخواند و در صورت مشکل Snapshot دوباره محاسبه کند.
- Worker برای ثبت رویداد به اجرای GitHub Actions وابسته نیست؛ مستقیماً داده را ذخیره می‌کند.
- GitHub Pages به Worker برای نمایش عمومی سوابق وابسته نیست.
- Secretها، تنظیمات Cloudflare و KV خصوصی در ZIP مخزن قرار نمی‌گیرند و هنگام Deploy باید حفظ شوند.

## تقویم و کارکرد یکپارچه

- نمایش تاریخ شمسی از timestamp خام و با timezone ثابت `Asia/Tehran` تولید می‌شود؛ `jalaliDate` قدیمی به‌عنوان منبع حقیقت استفاده نمی‌شود.
- مرورگر، Snapshot builder و Worker از منطق سازگار تقویم و ترتیب زمانی استفاده می‌کنند.
- کارکرد فعلی از قرائت‌های مطلق معتبر به‌همراه سفرهای ثبت‌شده محاسبه می‌شود؛ قرائت کاهشی بدون reset صریح به‌عنوان anomaly رد می‌شود.
- تمام قرائت‌های کیلومتر برای پیمایش تجمعی و telemetry مدل سوخت شمارش می‌شوند. این قرائت‌ها می‌توانند کیلومتر سوخت‌گیری ناقص را استنباط کنند، ولی بدون دادهٔ لیتر/سطح باک، مصرف سوخت را مستقیماً اندازه‌گیری نمی‌کنند.
- Snapshot با `calculationVersion: 10` تولید می‌شود و Data Loader Snapshotهای محاسباتی قدیمی‌تر را کنار می‌گذارد.
