Peugeot 206 Garage OS یک دفتر خودرویی داده‌محور برای ثبت رویدادها، قطعات، تعمیرات، مصرف سوخت، پیمایش، جریمه‌ها و هزینه‌های مالکیت است. ورودی اصلی از ربات تلگرام یا API مجاز دریافت می‌شود؛ Cloudflare Worker رویداد را اعتبارسنجی و در GitHub ذخیره می‌کند؛ داشبورد GitHub Pages داده‌ها را به وضعیت نگهداری، آمار و نمودار تبدیل می‌کند.

## برجسته‌ترین تغییرات نسخهٔ 3.28.0

- پروفایل فنی خودرو با ۲۰ شاخص پویا برای موتور، استاندارد آلایندگی، انتقال قدرت، ظرفیت‌ها، هندسه موتور، ابعاد، تایر، ترمز، تعلیق، عملکرد و ایمنی.
- تفکیک مشخصات «مرجع تیپ» از «تأییدشده با مدرک». مشخصات TU3 / K6D و Euro III برای تطبیق با مدارک خودرو نمایش داده می‌شوند و به‌عنوان مشخصات قطعی VIN معرفی نمی‌شوند.
- گسترش فرهنگ قطعات به **۱۲۶ قطعه در ۱۵ گروه** و **۳۵ سرویس/آزمون نگهداری**؛ هر قطعه سطح اهمیت، تناسب با خودرو، روش بازدید و علائم احتمالی دارد.
- شناسنامهٔ قطعه با برند، مدل، شماره فنی/OEM، سریال، مشخصات، تعداد، سمت/محل نصب، وضعیت، تأمین‌کننده، فاکتور و ضمانت.
- پذیرش تاریخ ضمانت شمسی و میلادی؛ تاریخ شمسی معتبر به تاریخ استاندارد میلادی تبدیل می‌شود و تاریخ نمایشی شمسی نیز نگه داشته می‌شود. تاریخ نامعتبر بی‌صدا پذیرفته نمی‌شود.
- نمودارهای تعاملی داشبورد: انتخاب هر ستون با کلیک، تمرکز صفحه‌کلید و نمایش مقدار دقیق همان بازه؛ پشتیبانی از بازه‌های ساعتی، روزانه، هفتگی و ماهانه.
- تحلیل عمیق‌تر قیمت وزنی هر لیتر، عملیات نگهداری، روند جریمه، هزینه، حجم سوخت، مسافت و سهم راننده.
- گزارش `/analysis` ربات شامل خلاصهٔ متنی و شش نمودار PNG: هزینه، سوخت، مسافت، سهم راننده، قیمت وزنی سوخت و فعالیت نگهداری.
- هویت بصری به‌روزشده با نشان رسمی PEUGEOT از منبع Stellantis Media، نشان جایگزین داخلی هنگام عدم دسترسی، بج‌های وضعیت، کارت‌های شیشه‌ای، بازتاب، لایه‌های نور و پشتیبانی از کاهش حرکت.
- نسخهٔ cache-busting مستقل `3.28.0` و تست‌های رگرسیون داده‌محور.


## ارتقای بصری 3.28.0

- لوگوی پژو در هدر و برچسب صفحهٔ اول به thumbnail محدود شده است؛ منبع بیرونی دیگر نمی‌تواند عرض یا ارتفاع صفحه را تغییر دهد.
- تصویر صفحهٔ مشخصات در قاب مستقل و کوچک‌تر نمایش داده می‌شود و ستون اطلاعات فنی فضای اصلی را حفظ می‌کند.
- پس‌زمینهٔ چندلایهٔ متحرک با لکه‌های نور فیروزه‌ای و بنفش به صورت CSS و بدون فایل ویدیویی/اسکریپت دائمی اضافه شده است؛ حرکت فقط transform/opacity است، روی کارت‌های شیشه‌ای بازتاب بصری ایجاد می‌کند و `prefers-reduced-motion` را رعایت می‌کند.
- ۹ تصویر گرافیکی اختصاصی WebP برای موتور، ترمز، خنک‌کاری، برق، گیربکس، تعلیق، تهویه، سوخت‌رسانی و چرخ‌ها به‌صورت محلی اضافه شده‌اند. تصاویر هر دسته در کارت سرویس با opacity پایین و ماسک تدریجی استفاده می‌شوند تا خوانایی اطلاعات و اعداد کم نشود.
- کارت‌های سرویس اصلی، سرویس‌های ثبت‌شده و دیکشنری سرویس‌ها بر اساس دستهٔ واقعی قطعه/خدمت رنگ، نور، تصویر و جزئیات تایپوگرافی جداگانه می‌گیرند.
- `README.md` و `botfather-commands.txt` با نسخهٔ جاری و دستورهای قابل استفادهٔ Worker هماهنگ شده‌اند.

تصاویر AI صرفاً برای تزئین کارت‌های دسته‌بندی تولید شده‌اند؛ مرجع فنی OEM، راهنمای تعمیر، شماره فنی یا اثبات سازگاری قطعه محسوب نمی‌شوند.

### کنترل اندازه لوگو و چیدمان

نشان‌های بیرونی در کادرهای ثابت با `width` و `height` صریح نمایش داده می‌شوند. قاب تصویر مشخصات نیز در دسکتاپ حداکثر ۲۷۰ پیکسل عرض دارد و در موبایل به بالای متن منتقل می‌شود. این محدودیت‌ها در فایل `assets/css/visual-refresh-v328.css` متمرکز شده‌اند تا تغییرات آینده نیازمند دستکاری چندین فایل CSS نباشد.

### هویت تصویری کارت‌های نگهداری

هر کارت یک `data-category` دارد؛ شناسهٔ دسته از کلید سرویس و دستهٔ قطعه استخراج می‌شود و در صورت generic بودن دستهٔ `service`، از نام کلید به دستهٔ تخصصی نگاشت می‌شود. اگر دستهٔ جدیدی در `data/config.json` اضافه شود، برای نمایش صحیح بهتر است رنگ، icon و در صورت وجود تصویر دسته نیز به `SERVICE_VISUAL_META` و `visual-refresh-v328.css` افزوده شوند.

## شروع سریع

۱. در چت خصوصی ربات `/start` و سپس `/guide` را بفرست.

۲. کیلومترشمار را با قرائت واقعی ثبت کن:

```text
/km 432500
```

۳. سوخت‌گیری جزئی هم کافی است؛ لازم نیست باک کامل باشد:

```text
/fuel 12l cost=360000 toman km=432620
/fuel 20l cost=700000 toman km=432820
```

۴. پیامک کامل راهور را مستقیماً برای ربات بفرست. پارسر شناسه‌ها، تاریخ، ساعت، مبلغ همان قبض و جزئیات تخلف را استخراج می‌کند؛ متن اصلی نیز حفظ می‌شود.

۵. برای شناسنامه فنی و قطعات:

```text
/vehicle
/partinfo سنسور دور موتور
/catalog
/services
/components
```

۶. برای گزارش‌های عددی و نموداری:

```text
/summary month
/fuelstats
/costs 100
/analysis month
```

## فرهنگ قطعات و نگهداری

| گروه | نمونه قطعات |
|---|---|
| موتور و آب‌بندی | واشر در سوپاپ، واشر کارتل، شلنگ هوای ورودی |
| سوخت و جرقه | انژکتور، شمع، وایر و اجزای فشار سوخت |
| خنک‌کاری | رله فن، مقاومت فن، اجزای رادیاتور و ترموستات |
| برق | سوئیچ، کابل اتصال بدنه، رگلاتور دینام، پشت‌آمپر |
| انتقال قدرت | پلوس چپ/راست، گردگیر پلوس |
| فرمان و تعلیق | بوش، ضربه‌گیر کمک، رک فرمان، پمپ هیدرولیک |

تعداد کل و جزئیات زنده از `data/config.json` خوانده می‌شود؛ جدول بالا فقط نمونه است. شماره فنی، بازه تعویض و سازگاری هر قطعه باید از روی VIN، کد موتور/گیربکس، نمونهٔ قطعهٔ نصب‌شده یا کاتالوگ سازنده تأیید شود. کد OEM یا فاصله سرویس ساختگی وارد نشده است.

## نصب و انتشار

### داشبورد

فایل‌های پروژه را در ریشهٔ مخزن `mehrdadmb2/peugeot-206-garage` جایگزین کن، داده‌های جدیدتر را حفظ کن، Snapshot را بساز و به شاخهٔ `main` Push کن. GitHub Pages سایت را منتشر می‌کند.

### Worker و ربات تلگرام

```powershell
cd worker
npm install
npx wrangler login
npx wrangler deploy
```

Secretهای موجود Cloudflare و Binding فضای خصوصی `GARAGE_PRIVATE_KV` باید حفظ شوند. ZIP شامل توکن‌ها یا شناسه محرمانه KV نیست؛ مقادیر واقعی را در سورس قرار نده.

## آزمون محلی

نیازمند Node.js 22 یا جدیدتر:

```bash
npm --prefix worker install
npm --prefix worker test
npm --prefix worker run check
node scripts/build-dashboard.mjs
```

تست‌ها شامل ساخت Snapshot، بارگیری جایگزین، رندر همه بخش‌ها، تاریخ شمسی، مدل سوخت، جریمه، قطعات، ضمانت، مسیرهای خصوصی مدارک، تحلیل تصویری و فرمان‌های Worker هستند.

## منبع داده و امنیت

- `data/logs/*.json` منبع رویدادهای خام؛ `data/dashboard.json` فایل محاسباتی مشتق‌شده و قابل بازسازی است.
- پیش از جایگزینی از `data/` نسخه پشتیبان تهیه کن و رویدادهای جدیدتر از ZIP را نگه دار.
- مدارک شخصی خودرو در GitHub Pages عمومی قرار نمی‌گیرند؛ API مدارک به Token و KV خصوصی متصل است.
- Secretهای Worker فقط در Cloudflare تنظیم می‌شوند.
- تاریخ‌ها در منطقه زمانی `Asia/Tehran` نمایش داده می‌شوند.
- تخمین مصرف، تخمین فیزیکی مبتنی بر داده‌های سوخت‌گیری است؛ کیلومترشمار بدون حجم سوخت، مصرف را اندازه نمی‌گیرد.
- مهلت جریمه یادآور مدیریتی است؛ وضعیت/مبلغ قطعی را در سامانه رسمی راهور بررسی کن.
