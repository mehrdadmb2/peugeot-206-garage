# 206 Garage — دفتر هوشمند پژو ۲۰۶

سامانه‌ی شخصی ثبت و تحلیل استفاده از خودرو با سه بخش:

1. **Telegram Bot** برای ثبت سریع فارسی/انگلیسی.
2. **Cloudflare Worker** برای اعتبارسنجی پیام، تحلیل ورودی، محاسبه‌ی موعدها، ارسال پاسخ و نوشتن داده در GitHub.
3. **GitHub Pages** برای داشبورد واکنش‌گرا، نمودارها، فهرست رویدادها و خروجی CSV/JSON.

> پروفایل اولیه در این نسخه `Peugeot 206 Type 2 · 1387` است. ۲۰۶ تیپ ۲ معمولاً هاچ‌بک است؛ ۲۰۶ SD سدان متفاوتی است. تصویر داخل پروژه یک تصویر برداری تزئینی است، نه عکس واقعی خودرو یا لوگوی رسمی. مشخصات دقیق موتور/تریم را از مدارک خودرو تأیید کن.

## امکانات

- ثبت کیلومترشمار مطلق و مسافت روزانه؛ برآورد کارکرد بر اساس خط زمانی رویدادهای ثبت‌شده؛ همچنین اختلاف دو قرائت کیلومترشمار در صبح/شب برای برآورد مسافت استفاده می‌شود.
- ثبت سوخت‌گیری با لیتر، هزینه، کیلومتر و علامت «باک کامل» برای تخمین مصرف در لیتر/۱۰۰ کیلومتر.
- ثبت سرویس‌های دوره‌ای و قطعات مصرفی؛ تعیین موعد کیلومتری و زمانی.
- یادآور زمان‌بندی‌شده‌ی تلگرام برای سرویس‌های ثبت‌شده که نزدیک موعد یا عقب افتاده‌اند.
- ثبت هزینه‌های معمول، کارواش، خرابی، تعمیر/رفع خرابی، جریمه و پرداخت جریمه.
- ثبت تاریخ شمسی یا میلادی، زمان با ارقام فارسی/انگلیسی و منطقه‌ی زمانی `Asia/Tehran`.
- گزارش هفته/ماه/سال، گزارش سوخت، گزارش جریمه‌ها، خروجی CSV داخل تلگرام و خروجی CSV/JSON در صفحه.
- ثبت داده در فایل‌های JSON ماهانه به‌جای یک فایل بی‌نهایت بزرگ؛ به‌همراه تلاش مجدد در تداخل هم‌زمان نوشتن GitHub.
- دستورهای کوتاه و ثبت متن طبیعی فارسی/انگلیسی.

## ساخت مخزن GitHub

- **Repository name:** `peugeot-206-garage`
- **Description:** `Telegram-powered Peugeot 206 maintenance log, fuel tracker, expenses and responsive GitHub Pages dashboard.`
- **Branch:** `main`
- **Pages source:** `Deploy from a branch` → `main` → `/(root)`
- فایل‌های پروژه را در ریشه‌ی repo قرار بده، نه داخل یک پوشه‌ی اضافی.

**حریم خصوصی:** برای استفاده‌ی رایگان معمول GitHub Pages، مخزن را عمومی در نظر بگیر. در مخزن عمومی، تمام فایل‌های `data/logs/*.json` و از جمله هزینه‌ها، جریمه‌ها، تاریخ‌ها و پیام‌های ثبت‌شده عمومی‌اند. آدرس خانه، مسیرهای رفت‌وآمد، شماره پلاک، VIN یا اطلاعات حساس را ثبت نکن. اگر خصوصی بودن داده‌ها ضروری است، قبل از استفاده پلن/امکان Pages برای مخزن خصوصی را بررسی کن و این معماریِ ذخیره‌ی داده‌ی خام در repo عمومی را به‌کار نبر.

## ساخت ربات تلگرام

1. در Telegram، به `@BotFather` برو و `/newbot` را اجرا کن.
2. **Display name پیشنهادی:** `206 Garage | دفتر هوشمند خودرو`
3. **Username پیشنهادی:** `Peugeot206GarageBot` (نام کاربری باید به `bot` ختم شود و جهانی یکتا باشد؛ اگر آزاد نبود، یک پسوند دلخواه مثل `Peugeot206LogBot` انتخاب کن.)
4. توکن BotFather را فقط به‌عنوان Secret در Cloudflare ذخیره کن؛ آن را در GitHub، HTML یا این README قرار نده.
5. شناسه‌ی عددی کاربر تلگرام خودت را به دست بیاور. ساده‌ترین روش، دریافت شناسه از یک ربات نمایش‌دهنده‌ی User ID است. راه جایگزین: پیش از تنظیم webhook، به ربات تازه‌ساخته‌شده پیام بده و از `getUpdates` API با توکن خودت `message.from.id` را بخوان. شناسه‌ی **کاربر** را برای `ALLOWED_TELEGRAM_USER_ID` لازم داریم.

## توکن GitHub

در GitHub یک **Fine-grained personal access token** بساز:

- فقط مخزن `peugeot-206-garage` را انتخاب کن.
- Repository permissions: `Contents: Read and write`.
- به `Actions`, `Workflows` یا دسترسی‌های غیرضروری نیاز نیست.
- این توکن تنها در Secret با نام `GITHUB_TOKEN` در Cloudflare ذخیره می‌شود.

## استقرار Cloudflare Worker از CMD ویندوز

این پروژه به PowerShell script (`.ps1`) نیاز ندارد. دستورات زیر را در **Command Prompt (CMD)** اجرا کن. Node.js نسخه‌ی LTS و npm باید نصب باشند.

### 1. آماده‌سازی

در `worker/wrangler.toml` مقدارهای زیر را ویرایش کن:

```toml
[vars]
GITHUB_OWNER = "YOUR_GITHUB_USERNAME"
GITHUB_REPO = "peugeot-206-garage"
GITHUB_BRANCH = "main"
```

`GITHUB_OWNER` را با نام حساب GitHub خودت جایگزین کن. سپس مطمئن شو فایل‌های اولیه‌ی repo، خصوصاً `data/config.json`, `data/index.json` و پوشه‌ی `data/logs/`، روی شاخه‌ی `main` قرار دارند.

### 2. نصب Wrangler و ورود به Cloudflare

```cmd
cd path\to\peugeot-206-garage\worker
npm install
npx wrangler login
```

### 3. تنظیم Secretها

برای `TELEGRAM_WEBHOOK_SECRET` یک رشته‌ی تصادفی طولانی بساز که فقط شامل حروف انگلیسی، عدد، `_` یا `-` باشد. همان مقدار باید در اسکریپت ثبت webhook نیز وارد شود.

```cmd
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
npx wrangler secret put GITHUB_TOKEN
npx wrangler secret put ALLOWED_TELEGRAM_USER_ID
```

پس از هر دستور، مقدار همان Secret را در prompt وارد کن. `ALLOWED_TELEGRAM_USER_ID` عدد شناسه‌ی کاربر مجاز است. توکن‌ها را در `wrangler.toml` یا فایل‌های وب قرار نده.

### 4. Deploy

```cmd
npx wrangler deploy
```

در خروجی، URL مربوط به Worker را می‌بینی، مثلاً `https://peugeot-206-garage-bot.<your-subdomain>.workers.dev`. آدرس واقعی خودت را استفاده کن.

تست سلامت:

```cmd
curl https://YOUR-WORKER-URL/health
```

اگر `configured` برابر `true` بود، سه Secret اصلی شناسایی شده‌اند. این تست دسترسی GitHub را کامل اثبات نمی‌کند؛ ثبت آزمایشی در تلگرام را هم انجام بده.

### 5. اتصال webhook تلگرام — بدون فایل PS1

همان CMD را باز نگه دار و سه متغیر زیر را برای همان پنجره تنظیم کن. مقادیر داخل نمونه را با مقدارهای خودت جایگزین کن؛ فایل `.mjs` توکن را ذخیره نمی‌کند.

```cmd
set "BOT_TOKEN=توکن_واقعی_BotFather"
set "WORKER_URL=https://آدرس-واقعی-Worker.workers.dev"
set "WEBHOOK_SECRET=همان_Secret_تلگرام_در_Cloudflare"
node scripts/set-webhook.mjs
```

اسکریپت، webhook و فهرست دستورهای منوی ربات را تنظیم می‌کند. باید از پوشه‌ی `worker` اجرا شود. اگر Node.js خطای شبکه داد، دسترسی به `api.telegram.org` را بررسی کن.

برای بررسی وضعیت webhook می‌توانی اجرا کنی:

```cmd
curl "https://api.telegram.org/bot%BOT_TOKEN%/getWebhookInfo"
```

## انتشار GitHub Pages

1. مخزن را باز کن → `Settings` → `Pages`.
2. در `Build and deployment`، گزینه‌ی `Deploy from a branch` را انتخاب کن.
3. شاخه‌ی `main` و پوشه‌ی `/(root)` را انتخاب و Save کن.
4. پس از انتشار، URL در همان بخش نمایش داده می‌شود، معمولاً `https://YOUR_GITHUB_USERNAME.github.io/peugeot-206-garage/`.

Worker رویداد را مستقیماً در `data/logs/YYYY-MM.json` ذخیره می‌کند و فهرست ماه‌ها را در `data/index.json` به‌روز می‌کند. GitHub Pages استاتیک است؛ تغییر commit شده ممکن است با کمی تأخیر روی سایت دیده شود. دکمه‌ی تازه‌سازی فایل‌ها را دوباره دریافت می‌کند.

## فرمت ثبت پیام‌ها

### کیلومتر و رانندگی

```text
/km 156000
کیلومتر ماشین شده ۱۵۶۲۰۰
/trip 85
امروز ۸۵ کیلومتر رانندگی کردم
امروز با این کیلومتر به خانه برگشتم ۱۵۶۲۸۰
```

`/km` یا پیام دارای کارکرد مطلق، کیلومترشمار را ثبت می‌کند. اگر دو عدد کیلومترشمار پشت سر هم ثبت شوند، برنامه اختلاف مثبت بین آن‌ها را به‌عنوان مسافت تخمینی حساب می‌کند. `/trip 85` نیز مسافت روز را ثبت می‌کند؛ وقتی بازه‌ی دو کیلومترشمارِ معتبر، همین پیام‌های /trip را پوشش بدهد، برای جلوگیری از دوباره‌شماری، اختلاف کیلومترشمار اولویت دارد. برای جلوگیری از حدس اشتباه، بعد از استقرار، پاسخ ربات به پیام‌های مبهم را بررسی کن.

### سوخت‌گیری

```text
/fuel 20l cost=700000 toman km=156200 full
۲۰ لیتر بنزین، هزینه ۷۰۰ هزار تومان، کیلومتر ۱۵۶۲۰۰
```

`full` یا «باک کامل/پر کردم» سوخت‌گیری را به‌عنوان باک کامل مشخص می‌کند. تخمین مصرف لیتر/۱۰۰ کیلومتر تنها وقتی نمایش داده می‌شود که حداقل دو رویداد باک کامل همراه با کیلومتر معتبر وجود داشته باشد؛ این تخمین به کامل‌بودن واقعی باک و دقت اطلاعات وابسته است.

### سرویس و تنظیم موعد

```text
/service oil cost=900000 toman km=156000
روغن موتور را عوض کردم؛ هزینه ۹۰۰ هزار تومان؛ کیلومتر ۱۵۶۰۰۰
/service air_filter cost=250000 toman km=157000
/interval oil 5000 180
/due
```

بعد از تعویض، ربات بر اساس **کیلومتر همان سرویس + بازه‌ی قابل تنظیم** کیلومتر موعد بعدی را محاسبه می‌کند. اگر کیلومتر همان سرویس ثبت نشود، موعد کیلومتری قابل اعتماد نیست. بازه‌های موجود در `data/config.json` تنظیم اولیه‌ی برنامه‌اند، نه ادعای مشخصات رسمی سازنده برای هر موتور/شرایط کارکرد.

### خرابی، تعمیر، کارواش و هزینه

```text
خرابی: صدای جلوبندی
/fixed 450000 toman جلوبندی تعمیر شد
/wash 180000 toman
/expense 250000 toman پارکینگ
```

ثبت «درست شد/تعمیر شد» آخرین خرابی باز را رفع‌شده می‌کند و هزینه‌ی موجود در پیام را روی همان رویداد ثبت می‌کند. قبل از بستن خرابی مطمئن شو رویداد باز درست است.

### جریمه

```text
/fine 500000 toman سرعت غیرمجاز km=156200
/fines
/paid 8-character-id
```

شناسه‌ی کوتاه جریمه در پاسخ ثبت و در صفحه نمایش داده می‌شود. `/paid` همان رویداد را پرداخت‌شده می‌کند و بدهی پرداخت‌نشده را به‌روز می‌کند.

### گزارش و خروجی

```text
/summary today
/summary week
/summary month
/summary year
/summary all
/fuelstats
/latest
/export
/export 2026-09
```

همچنین در داشبورد، فیلتر نوع رویداد، جست‌وجو، فیلتر ماه و دکمه‌های خروجی CSV/JSON وجود دارد.

## ساختار داده

```text
index.html
assets/css/style.css
assets/js/app.js
assets/img/206-white.svg
assets/img/206-sd-garage.webp  # تصویر سینمایی اختیاری برای نسخه SD
data/config.json
data/index.json
data/logs/YYYY-MM.json   # از اولین ثبت ایجاد می‌شود
worker/wrangler.toml
worker/src/index.js
worker/scripts/set-webhook.mjs
```

هر رویداد شامل شناسه‌ی یکتا، زمان ثبت، زمان رخداد، تاریخ میلادی و شمسی نمایشی، نوع رویداد و در صورت وجود کیلومتر، مسافت، لیتر، هزینه به ریال، شناسه سرویس و وضعیت پرداخت/رفع خرابی است. رابط کاربری هزینه را به تومان نمایش می‌دهد.

**تصویر خودرو:** تصویر پیش‌فرض `assets/img/206-white.svg` برای نمای تزئینی هاچ‌بک تیپ ۲ است. تصویر سینمایی اختیاری `assets/img/206-sd-garage.webp` هم در بسته قرار دارد؛ اگر خودروی تو واقعاً SD است، در `index.html` منبع تصویر در `img.car-art` را از `assets/img/206-white.svg` به `assets/img/206-sd-garage.webp` تغییر بده و متن `HATCHBACK` در کپشن را به `SEDAN / SD` تغییر بده. تصویر سینمایی تزئینی/تولیدشده است، نه سندی برای تأیید تریم یا مشخصات خودرو.

## تست محلی منطق Worker

از پوشه‌ی `worker` اجرا کن: `npm test` (یا `node test/smoke.mjs`). این تست‌ها با APIهای شبیه‌سازی‌شده اجرا می‌شوند و جایگزین تست نهایی با توکن‌های واقعی تلگرام، Cloudflare و GitHub نیستند.

## نکات عملی و محدودیت‌ها

- **این سیستم جایگزین ابزار تشخیص عیب یا دفترچه سرویس نیست.** فاصله‌های اولیه قابل ویرایش‌اند؛ مخصوصاً زمان‌بندی تسمه تایم، مایعات و ترمز را با مشخصات دقیق خودرو تطبیق بده.
- ورودی آزاد می‌تواند مبهم باشد. برای تراکنش حساس، دستور صریح همراه با کیلومتر/مبلغ و بازبینی پاسخ ربات مطمئن‌تر است.
- همه‌ی داده‌های ذخیره‌شده در GitHub به واحد ریال هستند و ورودی بدون واحد پول در الگوی تشخیص مبلغ به‌صورت تومان تفسیر می‌شود. برای جلوگیری از خطا، واحد «تومان» یا «ریال» را واضح بنویس.
- با وارد کردن اعدادِ «هزار» یا «میلیون»، واحد را صریح نگه دار؛ از عبارت‌های چندمعنا اجتناب کن.
- Worker تنها به `message.from.id` تعیین‌شده اجازه ثبت می‌دهد. هرگز توکن BotFather، توکن GitHub یا webhook secret را در مخزن قرار نده.
- ثبت هر پیام معمولاً یک commit برای فایل ماه و یک commit برای index ایجاد می‌کند. این برای دفتر خودرو با تعداد رویداد محدود مناسب است؛ اگر تعداد رویدادها بسیار بالا شد، ذخیره‌سازی پایگاه داده‌ای مثل D1 مناسب‌تر است.

## عیب‌یابی سریع

- **ربات پاسخ نمی‌دهد:** `getWebhookInfo` را بررسی کن؛ URL باید به `/telegram` ختم شود و `last_error_message` خالی باشد.
- **ثبت به GitHub ناموفق است:** در Cloudflare Worker Logs خطا را ببین، نام مخزن/شاخه، `GITHUB_OWNER` و مجوز `Contents: Read and write` توکن را بررسی کن.
- **پیام «اجازه استفاده نیست»:** شناسه‌ی `ALLOWED_TELEGRAM_USER_ID` را با `message.from.id` درست کن و دوباره `npx wrangler secret put ALLOWED_TELEGRAM_USER_ID` اجرا کن.
- **Pages خالی است:** وجود `data/index.json`, `data/config.json`، تنظیمات `main / root` در Pages و عمومی‌بودن مخزن را بررسی کن.
- **کیلومتر/هزینه درست تشخیص داده نشد:** از فرمان صریح مثل `/km 156000` یا `/fuel 20l cost=700000 toman km=156200` استفاده کن.
